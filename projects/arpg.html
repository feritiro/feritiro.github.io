02 / GAMEPLAY ARCHITECTURE

Dungeon Master architecture

Problem

The project needs to coordinate several gameplay responsibilities without placing every decision and behavior into one large manager class.

Approach

I use a central Dungeon Master that coordinates specialized systems. These systems report information to the central coordinator while retaining focused responsibilities.

  • Player Reaction Monitor
  • Spawner Directors
  • Difficulty Evaluator

03 / UI & ASSET MANAGEMENT

Gameplay Tag-driven asynchronous UI loading

Problem

UI requests should not require every caller to hold hard references to all possible UI assets or load every UI asset upfront.

Approach

Gameplay Tags identify the requested UI. The system uses the tag to resolve the corresponding UI asset and load it asynchronously.
